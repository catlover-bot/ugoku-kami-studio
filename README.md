# うごく紙工房

**描いた絵を、手で動かせる工作へ。**

カメのサンプルや自分の画像から、引っぱりタブでまっすぐ動く工作を設計するWebアプリです。選択・プレビュー・条件検査・原寸PDF・材料・組み立て手順を同じ設計版から作ります。

初期版の機構は直線運動だけです。回転・揺動・歩行・歯車・立体・モーターには対応しません。**実物未検証**で、紙質・摩擦・耐久性まで保証するものではありません。ソフトウェアはmainへ統合し、GitHub CIでDockerのビルド・実起動・手動操作・PDF取得を確認しました。Gemini Developer APIの実通信と一般公開は未確認です。Vertexは非公開の限定試験で1依頼の候補採用・同版PDF取得を確認し、試験サービスを削除しました。実行した検証と制約は [検証記録](docs/verification.md) を参照してください。

[Goal 005](docs/goals/005-product-experience.md) の入力・保存・工程・組立体験を維持し、[Goal 006](docs/goals/006-request-understanding.md) では希望の読み取りと訂正を改善しました。統合の許可は [Goal 004-R](docs/goals/004-resume-and-main.md) から継続しています。確認済み変更のコミット・mainへの通常統合・push・通常CIは許可されています。実Gemini、実物、初見の人、実スマートフォン、Cloud Run公開の未確認状態は、ソフトウェア統合と分けて管理します。過去Goalのpush保留や全体blockedの記録は当時の状態であり、現在の統合を止める指示ではありません。

[Goal 007-R](docs/goals/007r-local-ai-clean-ui.md) では、既存OllamaとローカルGemmaを使う接続を追加し、希望入力と候補の採否を同じ作業領域へ整理しました。Geminiを含むホスト型推論APIはこのGoalでは実行しません。設定・実測・WSLの起動方法は [AI接続の説明](docs/live-gemini.md) を参照してください。

[Goal 008](docs/goals/008-submission-ready.md)では、条件変更の助言も提示前にコアで検査し、公開に備えた接続復帰と提出素材を準備しています。2026-10-05 JSTに、本人の許可で非公開のCloud Run＋Gemma限定試験を行い、試験サービスは削除しました。初回AIは180秒で時間切れ、同一依頼のキャッシュが温まった状態では78.5秒で候補を作成し、採用した同じ版のPDF・保存再開まで確認しました。中断のHTTP400は修正してローカル回帰を確認しましたが、Cloud再試験はしていません。**公開運用・審査可能なURLの提供にはまだ進めません。** [限定試験の結果・費用・残存保管](docs/cloud-trial-008.md)を参照してください。YouTube投稿・Zenn提出は未実施です。

[Goal 009](docs/goals/009-vertex-comparison.md)では、公開候補としてCloud RunのWeb/API＋Vertex AIを準備しています。明示した`AI_PROVIDER=vertex`とADCを使う専用アダプターを追加し、接続表示と模擬通信を確認しました。**非公開Vertex試験では1依頼が約6.3秒で候補表示まで進み、採用・同版PDF・保存再開を確認しました。使用量の欠測により費用予約を維持し、残り3件は開始せず片付けました。** [実測・費用・片付け結果](docs/vertex-trial-009.md)を参照してください。既存Gemmaの実測・動画は別の記録です。[構成比較・料金根拠・次の限定試験案](docs/vertex-comparison-009.md)を参照してください。

## 起動

Node **24.20.0**（`.nvmrc`）/ npm **11.19.0**で開発しています。

```sh
npm ci
npm run doctor
npm run dev
```

http://localhost:5173 を開きます。開発APIはポート3001、Viteが `/api` を同一オリジンとして転送します。開始画面で自分の画像・サンプル・前の作品を選べます。APIキーなしで手動設計・保存・PDF取得ができます。

1. 開始画面の「自分の絵ではじめる」でPNG/JPEG/WebPを選ぶか、「サンプルで試す」を選ぶ。前の作品は一覧から続けられる。
2. 動かす部分を四角く囲む。ドラッグ・2点タップ・数値・矢印キーで修正できる。「原画像」で読み込んだ絵を確認し、動きの工程の「はじめ」「おわり」で背景や輪郭の切れ方を比べる。
3. 方向・距離・「絵の大きさを保つ」・A4枚数を指定する。「絵の大きさを保つ」は幅と高さの両方を固定する。「少し小さく／もう少し大きく」で実際の移動量の候補を出せる。「どう動かしたいですか？」へ「首を右に出したい。絵の大きさは保って、厚紙はA4で2枚まで」と書いて手動支援を使うこともできる。紙厚やすき間は「寸法・材料の詳細」にある。数値はEnterまたは欄を離れると確定、Escapeで入力を取り消せる。「元に戻す」「やり直す」で一回の編集を戻したり再適用できる。
4. 「動きをつける」で現在と候補を同じ縮尺・位置で比べ、「この案にする」か「この案を使わない」を選ぶ。狭い画面では同じ表示枠で切り替えられる。「もう少し大きく動かしたい。紙は増やさない」も現在値から計算する。条件に合わなければ違反理由と別の距離を確認する。
5. 「印刷して作る」で引く向き、材料、型紙枚数と説明書4ページを確認する。全部入りPDF・型紙だけ・説明だけを選んで取得できる。型紙はA4厚紙、説明は普通紙へ印刷する。
6. 「実際のサイズ／100%」、縮小なしで印刷し、50mm校正線を測る。「組み立てガイドを開く」で一工程ずつ読む。ガイドは最後に取得したPDFの版を保持し、その後の編集版と区別する。閲覧位置を保存するが、印刷・組立済みにはしない。実際に組み立てたら、両端・ガイド保持・接着面・手修正をその設計版に記録する。編集はこのブラウザへ自動保存される。画像付きプロジェクトや下書きを含む復元用ファイルも書き出せる。

紙面条件を満たさない場合に無断で縮小しません。型紙の紙枚数には8つの機構部品を含み、説明書ページを別に表示します。固定側の選択位置は通常白ですが、「元位置の背景を補う」で作者が指定した色や背景画像を使えます。変更前後を比べて採用すると、型紙の固定台紙にも同じ補正を印刷します。部品は増えません。自動背景復元ではありません。

背景が白く、動く部位を矩形で囲める絵に向いています。可動側は白い四角い紙で、透明PNGの透明部分も紙の白になります。背景補正後も、選択境界をまたぐ輪郭の切れや可動片の背景模様のずれは残り得ます。つながった首が伸びる見え方や任意の写真の分離は保証しません。元画像は書き換えず、完成予定の両端を確認して選び直せます。

## 保存とプライバシー

編集後、約600msの間隔で変更をまとめてIndexedDBへ自動保存します。作品一覧から複数の作品を開く・名前変更・複製・削除・読込・書出しできます。サンプルを開いて眺めるだけでは保存を増やしません。複製は新しい設計IDを持ち、実物確認の実績や記録下書きを引き継ぎません。削除は対象の作品名を確認します。クラウド保存・端末間同期はありません。

確定した画像・設計・記録と、工程・表示面・倍率・未選択状態・入力途中の数値・希望文・実物記録の下書き・取得したPDFのガイドと閲覧位置を分けて保存します。保存済み表示の後は、同じタブでの再読み込みでも続きを復元します。下書きを検査済み設計や実物確認済みにしません。保存の世代は設計revisionとは別で、閲覧状態の保存は設計hashを変えません。

旧localStorageの作品は保存・読戻し検証を経て移行し、元のデータを残します。旧v1/v2 `.ugoku.json` も画像・設計ID・hash・版別記録を保持して読めます。通常のプロジェクト書出しは確定済み内容、「下書きも含めて書き出す」は `.ugoku-recovery.json` で途中の入力も持ち出せます。どちらも読込時に検証し、秘密やAI認証状態を含めません。

保存拒否や容量不足では現在の編集を残し、保存失敗と最後の保存地点を表示します。再試行・ファイル書出し・作品整理を選べます。二つのタブが同じ作品を更新した場合は、同じトランザクション内で保存世代を照合し、古い編集による上書きを拒否します。「復旧用に別名保存」は競合先を変更せず、同じ作品の設計IDと実物記録を保った復旧スナップショットを別の保存先に残します。これは新しい設計IDを作る通常の「複製」とは区別します。

元絵・背景用画像のアップロードは5MB・1,200万画素・縦横8,192px以下の静止PNG/JPEG/WebP。サーバーでも実データをデコードし、メタデータを取り除いてPNGへ変換します。SVG/HTMLのアップロードや外部URL取得は行いません。利用者の画像をGitや公開サンプルへ保存しません。

プロジェクトファイル全体は45MB（UTF-8で45,000,000 bytes）、実物記録は1作品100件までです。記録の追加で上限を超える場合は下書きを残して知らせます。写真を減らすか小さい画像に選び直してから追加してください。ブラウザ内の保存容量はこれより小さい場合があり、書き出しと読込の容量制限とは別です。

AIに送るのは入力文・設計寸法・選択座標・検査結果です。画像本体は送りません。Developer APIのキーとVertexのADC認証はサーバー側だけで扱います。キー・認可トークンを`VITE_`変数・ブラウザ・ログへ渡しません。秘密値のない `.env.example` を用意しています。`.env` はGit対象外です。

## AIモード

| モード | 状態 |
|---|---|
| 手動 | APIキー不要。コアの決定的な検査を利用 |
| 模擬プロバイダー | テストだけで依存注入。本番の代替成功応答には利用しない |
| 実ローカルAI | 明示`AI_PROVIDER=ollama`。loopback・クラウド無効のOllamaへ接続。別モードへの自動切替なし |
| Gemini Developer API | 明示`AI_PROVIDER=gemini`とAPIキー。初期状態は無効。実通信は未確認 |
| Vertex AI | 明示`AI_PROVIDER=vertex`とADC。非公開Cloud Runで実推論1依頼・採用・PDFを確認。試験サービス削除済み、一般公開は未実施 |

希望入力は一つで、「寸法から案をつくる」「AIで案をつくる」を選べます。AIアクセスコード・モデル情報・実行記録は上部の「設定」にあり、コードは画面のメモリだけで扱います。`AI_PROVIDER`未設定は`none`で、保存済みGoogleキーや旧`AI_ENABLED=true`だけでは有効になりません。設定を入力しただけでは接続成功と表示しません。希望・設計・未確定入力が変われば、以前の候補や遅れて届く応答を反映しません。

AIは1機構の適用判断と寸法調整を行います。実ツールで候補を生成・検査し、元の設計版とセッションにひも付いた利用者の承認を経て反映します。固定条件やfail判定はモデルの文章で変更できません。[AI接続の設定と限定確認](docs/live-gemini.md) に設定場所・モデル・実測・正確なコマンドをまとめています。公開時の境界は [デプロイ手順](docs/deployment.md) を参照してください。

Goal 004のライブ確認は、通常の画面から比較・採用・同じ版のPDF取得まで進むL1を最初に1件だけ実行します。既定は実APIを呼びません。許可後の全試行は失敗・再試行を含め3件、モデル18回・ツール36回・AI処理270秒までで、台帳に開始前の枠を残します。通常のE2Eは専用ポート4183のAI無効サーバーを使い、起動済みの実AIサーバーを再利用しません。

AIの「実行の記録」から、モデル・実行ID・ツール・検査・取得できた使用量・採用した設計版を書き出せます。模擬実行は明示し、使用量未取得を0料金とは表示しません。依頼を編集すると古い候補は失効し、通信が途切れたときは「状況を確認する」で同じ実行を確認できます。

今すぐ印刷する手動設計の1件は [試作004・右へ泳ぐ魚](docs/prototype-004.md)。同じ版の原寸PDF・材料・組み立て手順・始点と終点の予定図・確認票をそろえています。実物の記録欄には、校正線、工程外の修正、ガイドの保持、10往復程度の初期チェック、写真4枚の向きを記録できます。実Gemini・印刷・組立・実スマートフォン・初見の人による確認は未実施です。

手動支援は対応語句を読むローカル計算で、Geminiや模擬AIではありません。「あと5mm」は現在値への追加、「5mm動かす」は絶対距離として区別し、cm・全角数字も換算します。「回転させず右へ」「左には動かさず右へ」の否定と希望を分け、距離が未指定なら現在値を保ちます。範囲外の値を上限へ丸めず、幾何条件を満たせない希望と実現可能な代案を区別します。

候補には「希望をこう受け取りました」と実際の差分が表示されます。曖昧なところは短い選択肢で指定でき、明確な依頼も「解釈を直す」から距離・方向・禁止方向を訂正できます。AI経路の訂正はサーバーへ送り直して検査します。依頼や基準の設計版が変わった古い訂正・候補は使えません。採用するまで確定作品は変わりません。

「紙は増やさない」は現在使用する型紙枚数を上限にし、採用後も条件を固定します。「現在の上限以内」は実際の使用枚数が同じという意味ではありません。上限を広げるには具体的な変更前後の確認が必要で、固定中の条件は解釈やモデルの返答で解除できません。手動で読み取れない条件は確認待ちとし、AIは既存のツールループ内で構造化した解釈を提案できます。日本語全般への対応や実モデルの理解性能を検証済みとはしていません。紙面探索は1mm刻みの移動量と棚詰め配置で、すべての配置が不可能と証明するものではありません。
