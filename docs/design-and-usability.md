# 紙の編集机 — 表示と操作の基準

Goal 003では作者の絵を大きく見せ、選ぶ・動かす・比べる・印刷する操作を順に示す。配色や装飾は作品の一部として印刷しない。

## 表示の役割

- 作業面は `#F6F4EE`、紙とパネルは白。主文字 `#292923`、補助文字 `#655F56`、主操作 `#A54732` を基準とする。
- 淡い `#DDD8CE` は装飾の区切り。入力の境界、選択、フォーカスは別の見える線で示す。
- 少数の余白・罫線・角丸を使い、本文は16px程度。開発用ID、ハッシュ、生ログは詳細へ置く。
- 各工程の次の行動を一つ強調する。再生、保存、候補の採用は目的の異なる操作として名前を付ける。
- 完成予定は実際の台紙と可動片の重なりを示す。編集補助や仕組みの線は表示を切り替えられる。
- 背景補正は作者が選ぶ変更。元絵と候補を見比べ、採用前に現在の作品へ適用しない。自動復元とは呼ばない。
- 現在と候補は共通の表示範囲・縮尺・基準位置・再生位相で比べる。印刷するのは採用済みの設計。
- ズームや表示面の切替は閲覧。設計版、ハッシュ、記録の対象を変更しない。
- 寸法の確認と実物での確認を区別し、実物未確認の試作を出力できる。

## アクセシビリティの確認基準

2026-10-03にW3C公式のUnderstanding文書を確認した。これは採用基準の説明であり、この製品のWCAG準拠を宣言するものではない。

| 対象 | 基準と確認方法 |
| --- | --- |
| 文字 | 通常文字は4.5:1、大きな文字は3:1。CSSの前景と実際の背景色を計算し、閾値を丸めない。[R1](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) |
| 操作・状態 | 識別に必要な境界や状態を隣接色に対し3:1で示す。装飾罫線のすべてに適用する要件ではない。[R2](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) |
| 操作領域 | 主要操作は製品目標として44×44 CSS px程度。WCAG 2.2 AAの原則は24×24で、間隔・同等操作・行内などの例外がある。[R3](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum) |
| 選択操作 | ドラッグ以外にクリック／タップだけで完了できる経路を用意する。キーボード経路は別に検証する。[R4](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements) |
| フォーカス | AAの最低条件は作者の要素で対象が完全に隠れないこと。製品としては対象全体が見えることを目指し、Tab移動・固定要素・閉じた後の復帰を確認する。[R5](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum) |
| リフロー | 320 CSS px相当でフォームと文章に横スクロールを要求しない。二次元図の例外をページ全体へ広げない。[R6](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) |

候補トークンの計算値（白／作業面）: 主文字14.63／13.30、補助文字6.32／5.74、アクセント5.92／5.38、装飾線1.42／1.29。実画面の半透明色・背景・状態は別に測る。

動きを減らす設定では自動再生を抑え、手動の始点・終点確認を残す。毎フレームの位置をライブ通知しない。日本語変換中のEnterで依頼を送らず、文字欄のUndoを設計のUndoが奪わない。

## 自動確認と記録

- 代表画面は1440×900、1280×800、1024×768、390×844、360×800。320 CSS px相当とPCの200%相当を別に扱う。
- viewportの縮小、CSS zoom、devicePixelRatioの変更、ブラウザ自身のズームを混同しない。模擬なら方式と限界を記録する。
- コントラストは計算、操作領域は実際のDOM矩形、フォーカスは実Tab操作と表示位置で確認する。自動ツールの通過だけで使用感を実証したとしない。
- U1〜U8を既存のS1〜S8に対応付け、設計版・座標・採用前後・保存復帰・PDFの内容も検証する。
- 模擬AIはテスト内HTTPまたはモデル通信だけを置換する。実Geminiの検証とは区別する。
- 証拠は `artifacts/goal003/` に保存し、入力、版・ハッシュ、viewport、表示モード、確認種別をmanifestへ残す。
- 旧Goalの証拠を新しい結果で上書きしない。テスト件数は全体実行と部分再実行を単純加算しない。

応答性は同じ入力のサイズ・画素数・ハッシュ、ブラウザ版、viewport/DPR、実行回数、cold/warm条件を記録する。選択確定→描画、数値調整→描画、採用→描画、PDFクリック→ダウンロードを個別に測る。PDFがフォントの取得を含むかも記録し、ローカル処理時間を端末・ネットワーク・実APIを含む全体性能と呼ばない。

実ブラウザの200%は `npx tsx scripts/check-browser-zoom.ts` で確認できる。一時プロファイルとローカル検証用拡張を使い、[Chrome公式のtabs.setZoom](https://developer.chrome.com/docs/extensions/reference/api/tabs#method-setZoom)で2倍を設定し、getZoomと実viewport幅を照合する。[Playwright公式の拡張検証手順](https://playwright.dev/docs/chrome-extensions)に従い、完了時にプロファイルを削除する。製品へ拡張を追加する処理ではない。結果・画面は `artifacts/goal003/usability/browser-zoom-200.*`。別途E2Eで確認する640px幅は、200%相当のリフロー模擬として区別して残す。

応答時間は `npx tsx scripts/measure-usability.ts` で、保存済みの代表入力 `artifacts/goal003/inputs/pattern.png` を実画面へ読み込んで測る。任意の別入力は `MEASURE_INPUT_PATH`、結果名は `MEASURE_REPORT_NAME` で指定できる。各操作3回、イベント時刻から確定DOMと次の描画機会までを記録し、PDFだけは実ファイルが完成してダウンロードを開始するまでを測る。長時間タスクとフォント取得も結果JSONへ残す。

## 初見の成人による確認手順

実施者は操作説明を先にせず、次の課題だけを渡す。参加者がいない場合は未実施と記す。

1. ご自身が用意した画像を読み込んでください。
2. 一か所を選び、意図した向きと距離で動かしてください。
3. 変更候補を比べ、使いたい案を採用してください。
4. 作るために必要な資料を出し、何を何枚印刷するか説明してください。
5. 保存して画面を開き直し、続きから操作してください。

観察者は開始・完了時刻、最初に迷った場所、誤操作、戻れたか、助言した言葉と時点、各課題の完了可否を記録する。終了後、現在の作品と候補の違い、印刷倍率、実物で未確認の点を本人に尋ねる。参加者の許可なく画像・発言・画面を外部へ送信しない。

開発者自身の操作とE2Eは利用者テストに数えない。ブラウザのスマートフォン模擬は実機確認に数えず、PDF確認は紙工作の動作確認に数えない。
