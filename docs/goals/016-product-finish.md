# Goal 016 — 現行UI・現行実AIへの統一と、製品版UI/UXへの最終仕上げ

うごく紙工房について、提出直前の最終改善を行ってください。
今回は、提出素材の差し替えだけではなく、アプリ本体も「より製品版らしいUI/UX」に整えてください。

## 0. 今回の目的

次の3点を同時に達成してください。

1. 提出用の画像・動画・審査手順から、旧画面をなくす
2. 実AIの紹介部分を、現在のUI・現在の公開版・現在の運用条件に一貫させる
3. アプリ本体を、ユーザーにとってもっと分かりやすく、AIが作った感の少ない製品版の見た目・操作へ改善する

今回は「なんとなく見た目を変える」ではなく、
- 作品中心
- 操作が自然
- 説明が短く明快
- 状態が分かる
- 画面が人間のプロダクトらしい
ことを重視してください。

## 2. 最優先で直すこと

### A. 提出素材から旧画面をなくす
今の提出候補動画・画像・説明に、旧UI・旧レイアウト・旧導線が残っていないか確認し、
すべて現行UIへ置き換えてください。

対象：
- 画像4枚
- 紹介動画
- README / 対応表
- 審査手順
- 必要に応じて紹介文中のUI説明

古い画面を「履歴」として出す必要があるなら、
その意味が明確な場合だけ短く使ってください。
曖昧に混ざって見える状態は不可です。

### B. 実AIを現在のものに統一する
現在の公開版・現在のUI・現在の運用条件で、
実AIの確認をやり直してください。

条件：
- 追加費用は既存管理枠の中に収める
- 必要最小限の実行にする
- 追加モデル呼び出しは、原則 1依頼・必要最小限の送信回数
- 追加実行前に、現行の受付条件・台帳・停止条件を確認
- 追加実行が不要なら、その理由を明確に報告

理想は、
「現行UIで希望入力 → 実AIで候補生成 → 比較 → 採用 → 同版PDF → 保存再開」
までを、現在のUIのまま1本通すことです。

もし安全性・費用上の理由で完全な再実行が難しいなら、
少なくとも
- 現在のUIでの実AI場面
- 現在のUIで採用後の比較・PDF
- 現在の運用条件との整合
が取れるようにしてください。

手動候補や模擬応答を、実AIの成功例として見せないでください。

## 3. アプリ本体のUI/UXをさらに製品版らしくする

前回のGoal013で改善した内容を土台にしつつ、
今回はさらに「人が作ったプロダクト感」を強めてください。

### デザイン方針
- 白・薄いグレー・落ち着いた差し色を基本にする
- 強い装飾、過剰なカード、過度な影、丸すぎるUI、説明だらけの見た目を減らす
- 余白・整列・文字階層・細線で整理する
- AIサービスによくある“雰囲気でまとめたUI”を避ける
- 作品と操作を主役にし、宣伝的な見出しや過剰なコピーを減らす

### 参考にするOSS / 実アプリ
前回のExcalidraw / Penpot / diagrams.net / Krita / Radix系の整理を活かしつつ、
今回はさらに「プロダクトとしての自然さ」を重視してください。

特に参考にする観点：
- Excalidraw：編集面を主役にする
- Penpot：状態ごとの右パネル整理
- draw.io：選択状態で切り替わる設定の分かりやすさ
- Notion / Linear / GitHub Projects のような
  “静かで整っていて、主張しすぎないプロダクトUI” の情報整理感
  （見た目のコピーではなく、整理原則の参考）

### 今回の改善ポイント
以下を重点的に直してください。

#### 3-1. 初見ユーザーにやさしい導線
- ホームで「何から始めるか」を明確にする
- 「自分の絵ではじめる」「サンプルで試す」を主導線として整理
- “このアプリで何ができるか” を短く一目で分かるようにする
- 機能紹介カードを増やさず、短い説明で済ませる

#### 3-2. 動きをつける画面の理解しやすさ
- 「何を設定しているのか」を明快にする
- 方向・距離・固定条件・希望文入力を整理する
- AIを使う操作と、手動・寸法支援を使う操作を混乱しないようにする
- 表示倍率・再生・裏のしくみの切り替えを、作品の近くに整理する
- 右パネルの情報の優先順位をさらに磨く

#### 3-3. 比較・採用画面の分かりやすさ
- 現在 / 希望 / 候補 の区別をもっと一目で分かるようにする
- 何が変わり、何が維持されたかを短く示す
- 「採用する」「戻る」を迷わないようにする
- 検査内容は主役にせず、詳細として扱う

#### 3-4. 印刷・組立画面の製品感
- 型紙 / 説明 / 全部入り の違いを直感的に理解しやすくする
- 「取得するもの」が分かりやすい見せ方にする
- PDFを取る前後で不安にならないような文言にする
- 組立ガイドも “実用品” として見やすくする

#### 3-5. 状態表示・エラー表示
- 保存中、保存完了、失敗、競合、AI未設定、受付制限などを分かりやすく
- 通常時は静かに、必要時だけ十分な情報を出す
- “エラーだから赤い箱をたくさん見せる” ではなく、
  行動につながるメッセージにする

#### 3-6. モバイル・狭幅
- PC版の縮小ではなく、必要な操作が自然に続くようにする
- スクロールが長すぎないこと
- ソフトキーボードと入力欄が干渉しないこと
- 主要ボタンが押しやすいこと

## 4. 壊してはいけないもの

以下は維持してください。

- 幾何・検査・設計版の整合
- 同版PDF・組立ガイド
- 保存再開
- 旧ファイル読込
- 自動保存
- 容量超過対応
- 2タブ競合対応
- AI受付制御
- 台帳・停止設計
- 監視・期限停止
- 現在の予算管理方針

UIの変更で、既存の設計・保存・費用管理・審査導線を壊さないでください。
