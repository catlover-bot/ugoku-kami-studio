## 2. まず入力とUndo/Redoを製品品質にする

現在の数値欄は、onChangeから数値化してpatchを呼んでいます。
これを、入力途中と確定した設計を分ける方式へ改善してください。

- 数値欄に文字列のdraftを持つ。
- 空欄、小数入力中、IME変換中を許容する。
- 入力途中の空欄を0として設計へ送らない。
- 原則Enterまたはフォーカス移動で、一度だけ検証・確定する。
- Escapeで直前の確定値へ戻す。
- 無効な値はその欄の近くに理由を示し、
  最後に成立していた設計を維持する。
- 入力の途中でエラーバナーへ画面を飛ばさない。
- Enterとblurで二重確定しない。
- 作品切替やAI応答と、入力draftの競合を処理する。

スライダーと選択枠は、操作中に軽量プレビューを返し、
一回の操作終了を一回の履歴として確定します。

一回のドラッグを戻すために、
何十回もUndoする挙動にしません。
pointercancelは開始状態へ戻します。
キーボード調整も意味のある単位で確定します。

「元に戻す」と「やり直す」を別々に実装します。
新しい編集を確定したらRedoを無効化します。
文字入力欄の通常のUndoや日本語変換を奪いません。

入力途中のdraftを、
検査済み設計・印刷データ・AI実行の基準に混ぜません。
AI実行や印刷の前に、確定・訂正・取消しを選べるようにします。

Undo/Redoでも設計版と承認の保護を維持し、
実物記録を消したり、別作品へ移したりしません。

## 3. 自動保存と、小さな作品一覧を実装する

### 作品一覧

同じブラウザ内に複数作品を残せるようにします。

必要な機能:
サムネイル、名前、更新日時、続きから開く、
名前変更、複製、削除、ファイルの読込・書出し。

フォルダ、タグ、検索、共有、アカウント管理は不要です。

開始画面には、
「自分の絵ではじめる」
「サンプルで試す」
「前の作品を続ける」
を簡潔に置きます。

新しい作品で前の作品を上書きしません。
サンプルを試すだけで、空の作品を大量に作りません。

複製には新しい設計IDを付け、
元の実物確認を複製の実績として引き継ぎません。

削除時は対象を明示して確認し、
編集中の作品や記録draftを無言で失わせません。

### 自動保存・復元

IndexedDB等の非同期ストレージを使い、
保存・読戻し・移行を扱う薄いrepository層を作ってください。

既存のDesignDocumentと検査コアは維持します。
大きな状態管理フレームワークを導入する必要はありません。

- 確定した変更後、短い間隔でまとめて保存する。
- ドラッグの全フレームで画像全体を書き込まない。
- 保存中／保存済み／保存失敗を実結果に合わせる。
- 保存完了した地点と、未保存部分を区別する。
- 編集工程、未確定の選択、入力中の実物記録は、
  復元用draftとして区別して扱う。
- 不完全なdraftを、検証済み設計や実物記録にしない。
- 再開時にAIを自動実行・自動承認しない。
- APIキー、アクセスコード、認証トークンは保存しない。
- 閲覧工程やズームの保存で設計ハッシュを変えない。
- 設計revisionと保存の世代を区別する。

旧localStorageの作品と、
既存v1/v2の.ugoku.jsonを読み込めるようにします。

移行は再実行しても重複しないものにし、
保存・読戻しの確認前に旧データを消しません。
破損した一作品によって、他の作品を消しません。

複数タブでは、書込み時にも世代を確認し、
古い保存で最新版を上書きしないようにします。

競合時は「別のタブで更新されています」と示し、
自分の編集を別作品として残すなどの復帰手段を用意します。

保存領域の拒否・容量不足でも現在の編集とdraftを保持し、
ファイル書出しや不要データの整理へ進めます。
既存作品を勝手に削除しません。

現行45MBのプロジェクト上限と画像・記録上限は維持します。
保存方式の変更を理由に、
書出したファイルを読戻せない不具合を再発させません。

「このブラウザ・このサイトへの保存」と明記し、
別端末や公開URLへ自動同期されるように見せません。
ファイルへのバックアップも残します。

## 4. 制作画面を、利用者の言葉と操作へ整理する

Goal 003の「紙の編集机」の方向を維持します。
別の配色・ブランドへ全面変更しません。

上部:
作品名、保存状態、元に戻す／やり直す。

中央:
大きな作品プレビュー。

脇:
今の工程に必要な設定と、次の操作。

ホームを追加しても、
「絵を選ぶ→動きをつける→印刷して作る」
という制作の3工程は増やしません。

重要な希望を詳細設定の外に出します。

- 動かす部分。
- 動く方向・距離。
- 絵の大きさを保つ。
- 型紙はA4で○枚まで。

「絵の大きさを保つ」は幅と高さの両方を保護します。
紙枚数の上限を、配置処理やAIが勝手に変更しません。
手動・AI・検査で同じ条件を使います。

紙厚、すき間、生ログ、設計ハッシュなどは
必要なときに読める詳細に残します。

工程ごとに表示を整理します。

- 絵を選ぶ: 元画像、動かす枠、選択の直し方。
- 動きをつける: 再生、条件、変更案、同縮尺比較。
- 印刷して作る: 用紙、出力、組立への案内。

すべての工程に同じツール群を並べません。
ただし、必要な裏面・印刷図などを見つけられなくしません。

開始時に長い説明を読ませず、
実際に使える入力例と短いガイドを表示します。
万能な背景復元や輪郭分離は宣伝しません。

背景・輪郭に限界がある場合は、
画像の近くで現在の見え方と修正方法を確認できます。
きれいな別サンプルへの差し替えで不具合を隠しません。

## 5. AIを使う操作も、製品の導線にする

既存のAIアダプターとツールループを利用します。
新しい会話システムを別に作りません。

希望の入力
→ 守る条件
→ 候補
→ 何が変わったか
→ 採用／却下

を一つの流れとして見せます。

設定や生ログを主役にせず、
変更箇所・守った条件・残る問題を短く示します。

AIアクセスコードが必要なら、
「AIを利用する」の設定箇所へまとめます。
既存の認証は解除せず、秘密はメモリ内に限定します。

設定があるだけで、接続成功や実API検証済みと表示しません。
AI未接続時も手動で編集・保存・印刷できます。

通常の制作画面に、
運用者向けの環境変数やデプロイ手順を並べません。

手動支援・模擬AI・実Geminiを区別します。
見た目を一貫させるために、その区別を消しません。

## 6. 印刷後の組み立てまでつなぐ

従来の全部入りPDFを維持し、次を選べるようにします。

- 型紙だけを保存する。
- 組み立て説明だけを保存する。
- まとめて保存する。
- 組み立てガイドを画面で開く。

すべて同じ設計版・生成系を使います。
型紙用の新しい寸法計算器を別に作りません。

型紙は厚紙何枚、説明は普通紙何ページかを明示します。
50mm校正線、A4実寸、100%印刷、部品番号を維持します。
PDF分割で寸法やページ順が変わらないことを確認します。

ダウンロードしただけで、
「印刷済み」「組立完了」「動作確認済み」にしません。

組立ガイドには、一工程ずつ大きく読む表示を追加します。

前へ／次へ、全工程、今回の部品、
表裏、接着する場所としない場所を確認できます。
既存の工程データから生成し、
一覧と一工程表示で説明を別管理しません。

取得した型紙の版を固定し、
編集中の作品が変わっても、
組立ガイドを別の版へすり替えません。

「取得した型紙の版」と「現在編集中の版」を区別します。
ガイドの閲覧進捗と、実物で確認した記録も区別します。

## 7. デザイン・応答性の完成条件

ラベル、余白、罫線、文字サイズ、ボタン、
hover／pressed／disabled／error／loading／focusをそろえます。

装飾カード、発光、過剰な影、
青紫グラデーション、大きな宣伝領域は追加しません。

一つの状態に対して、次の主操作を一つ目立たせます。
重大エラー、保存失敗、実物未確認は隠しませんが、
同じ警告を各パネルに繰り返しません。

数値入力や候補表示で、
フォーカスを勝手に移動しません。
日本語変換のEnterで依頼を誤送信しません。

狭幅では読める一列構成にし、
固定ボタンで本文・フォーカス・
ソフトキーボードを隠さないようにします。

主要タップ領域44px程度は製品の目標です。
WCAG 2.2 AAの最低値と混同しません。

文字コントラスト、色だけでない識別、
2点タップ・キーボード代替、動きの低減を維持します。

再生のフレーム更新で、
保存、PDF生成、設計履歴を実行しません。

必要な範囲でApp.tsxから
保存、編集状態、工程UIを分離します。
大規模な書き直しや状態管理基盤の導入は不要です。

性能改善を報告するときは、
同じ入力・環境・計測区間の変更前後を示します。
メモ化しただけで速くなったと断定しません。

## 8. 受入テスト

既存S1〜S8、U1〜U8を維持し、以下を確認します。

P1:
新規状態から、自分の画像→選択→希望→候補採用→出力。
詳細な機構設定や接続設定を開くことを必須にしない。

P2:
数値の全消去、小数、無効値、Enter、blur、Escape。
draft中に確定設計が変わらず、二重確定しない。

P3:
一回のドラッグを一回で戻せる。
Redo、新規編集後のRedo破棄、記録保持が正しい。

P4:
保存完了後の再起動で、画像・背景・工程・draftを復元。
保存途中、拒否、容量不足を正しく扱う。

P5:
3作品の切替・複製・削除・再開。
旧保存データの移行、v1/v2読込み、容量上限、
二つのタブの競合、破損した一作品からの回復。

P6:
AI未接続・失敗・中断・遅延応答でも作品を失わない。
古い候補を適用せず、認証情報を保存・書出ししない。

P7:
型紙のみ・説明のみ・全部入りの実ダウンロード。
寸法・ページ・版・組立ガイドの対応を確認する。

P8:
ホーム・編集・候補・印刷・組立をPCと狭幅で操作。
320px相当、200%拡大、IME、キーボード、
タップ代替、フォーカス、コントラストを確認する。

Chromiumに加え、利用可能ならPlaywright WebKitで、
保存・画像・PDF導線の代表経路を確認します。
WebKitの自動試験を実iPhone確認と呼びません。

手動保存を前提にした旧テストは、
仕様変更の理由を残して改訂します。
データ保持や寸法の保証を落とすために削除しません。

画面は実ブラウザで操作し、
PDFはレンダリングして確認します。
スクリーンショット生成だけで目視完了としません。

## 9. mainへ小さく統合する

順序は次です。

A. 入力draft、一操作一履歴、Undo/Redo。
B. 保存移行、自動復元、最小の作品一覧。
C. 工程別UI、AI導線、印刷分割、組立ガイド。
D. 横断回帰、表示と性能の仕上げ。

各まとまりを検証後にmainへ統合します。
不完全なデータ移行をmainへ入れません。

作業ブランチpush、通常のmain統合・push、
必要なPR、CI確認は引き続き実行対象です。
保護ルールを守り、force pushや無断解除をしません。

各統合で現行の
npm ci
npm run doctor
npm run check
npm run test:e2e
npm run examples
と、対象SHAのCIを確認します。

既存コンテナ検証を維持し、
最終版でも主要な製品導線を確認します。

実APIの許可、実物、参加者、Cloud Run公開は、
それぞれ独立した外部確認です。

それらが未完了でも、
今回の実装・回帰・main統合は進めます。
通常CIへ有料API実行を追加しません。
