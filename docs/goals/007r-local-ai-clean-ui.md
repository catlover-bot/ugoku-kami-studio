# Goal 007-R — ローカルAIを使い、制作画面を簡潔にする

## 目的と今回の変更

うごく紙工房の開発を継続してください。利用者はAPI料金を心配しており、オープンモデルでの動作と、情報を詰め込みすぎないUI/UXを希望しています。

旧Goal 007の「有料Geminiの限定試験を優先する」という実行順を変更します。今回の中心は、ローカルのGemmaによる実推論と、既存機能の見せ方の整理です。Geminiの既存実装は壊さず残しますが、有効化やAPI実行はしません。未完了の旧Goalや既存差分を消さず、方針変更を記録してください。

モデルの追加を理由に、新たな設定カード・チャット列・診断画面を常設しないでください。価値は「自分の絵を、迷わず動く工作へ設計できること」です。

## 2. 費用とネットワークの境界

- 今回はGeminiを含むホスト型推論APIを呼ばない。無料枠と思われるキーでも自動使用しない。
- Google Cloudの課金有効化、リソース作成、公開、IAM変更、GPUレンタルをしない。
- ローカルモデルが遅い・未起動・失敗したとき、有料APIやOllama Cloudへ自動フォールバックしない。元の作品を保持し、利用者が手動編集へ戻れるようにする。
- `--authorize-paid-api`や`LIVE_API_AUTHORIZED=yes`をローカル試験に流用しない。
- 本機の計算資源・ディスク・電力を使うことと、外部推論APIの課金がないことを区別する。「全運用費が永久に無料」と表示しない。
- 初回モデル取得の外部通信と、取得後のローカル推論を区別する。取得を含めて完全オフラインだったと報告しない。

## 3. 既存WSL環境を確認し、小型Gemmaを一つ選ぶ

まずOllamaの有無・版・実行中プロセス・ローカルモデル一覧、CPU/GPU、WSLから利用できるメモリとディスクを確認する。Windows側の別インスタンスとWSL側を混同しない。既存のモデルや他プロジェクトの設定を消したり、推論プロセスを無断停止したりしない。

採用候補はGoogle Gemmaの小型量子化モデルとする。公式Ollamaカタログでは `gemma4:e2b-it-qat` が掲載されているが、モデル名だけで動作を保証しない。導入済みOllamaとの互換性、正確なタグ・digest・量子化・ライセンス・必要なストレージを確認する。

まず既存の適切なローカルモデルを再利用できるか確認する。必要なら公式配布の候補一つに絞って取得する。多数のモデル、巨大な標準タグ、クラウドタグを自動ダウンロードしない。OS全体の更新・sudo権限が必要なら、その操作のみ分離し、UI改善やアダプター開発は続ける。

モデルファイルのサイズ、実行時RAM、コンテキスト用メモリは同じではない。公称128K等をそのまま設定せず、現行のプロンプトとツール定義が収まる小さなコンテキストを選ぶ。保護条件や必要な履歴を黙って切り捨てて収めない。

CPU推論も選択肢にするが、快適に動くと先に断定しない。並列実行はまず1。必要な出力だけ生成し、ロード時間と推論時間を分けて測る。小型モデルで不足した場合も、無断で有料モデルへ切り替えない。

## 4. ローカル専用の接続を実装する

既存サーバーからOllamaのローカルAPIを呼ぶ。ブラウザから任意の推論URLを指定させない。

- Ollamaはループバック限定で使う。既存のポートを確認し、アプリのサーバー設定で明示したループバック接続先だけ許可する。
- Ollamaサーバープロセス自体でクラウド機能が無効であることを確認する。`OLLAMA_NO_CLOUD=1`等をアプリ側だけに設定して済ませない。
- `:cloud`等のクラウドモデル、リモートモデル、外部リダイレクト、任意URLプロキシを拒否する。モデルがローカルにあるかメタデータも確認する。
- セキュリティ保護、セッション、実行制限、承認、設計版のチェックを外さない。
- ローカルモデルは実AIであり、`injected-test`や模擬Geminiと表示しない。provider・モデル・実行モードは明示的に扱う。

構成案は `AI_PROVIDER=none|ollama|gemini` 相当。ただし既存設定と統合し、重複する有効フラグを増やさない。未設定・不正設定でクラウドを選ばない。保存されたキーが存在しても、今回のローカルモードではGeminiを構築・呼出ししないことを検査する。

現在のModelProviderはGoogle SDKのContent/Response型に依存している。必要最小限の境界で、既存ループが扱う会話・ツール要求・結果を正規化し、Ollama用アダプターを追加する。Googleの署名等のprovider固有情報は当該アダプター内で保持し、互換性を壊したりローカルモデルへコピーしたりしない。

Ollamaのネイティブtool callingを、採用するモデルと実ランタイムで確認して使う。スキーマ制約JSONで代替する場合も、単なる会話文ではなく許可されたアクションを返し、既存のツール実行・再検査へ接続する。任意の生成コードをeval・シェル実行しない。

一つの経路で「依頼→解釈／候補→ツール検査→必要な調整→比較→採用→同じ版のPDF」までつなぐ。新しい独立した設計コアは作らない。

## 5. AIの役割を狭く、実用的にする

- AIに任せるのは、希望の解釈、許可された変更案、検査結果を受けた再調整。寸法計算、紙面配置、固定条件、最終採用は既存の確定的処理を使う。
- 曖昧な否定、相対量、単位、希望値と代案、紙上限の承認というGoal 006の改善を維持する。
- ツール引数・返答サイズ・未知のツール・途中で切れた応答を検証する。正しいJSONを意味的正解とみなさない。
- 成功台本、用意した固定回答、手動支援への無言の差し替えで、実モデル成功を装わない。
- 上限と中断を実装し、CPUの遅さを無限待ち・無限再試行で隠さない。送信済み要求の停止と、その後の処理・候補適用の禁止を区別する。
- 操作ごとに推論を起動しない。ドラッグ・スライダー・自動保存・再生はローカルの通常処理だけ。AIは本人が「案をつくる」を押したときだけ起動する。
- 内部思考、長いツール実況、生JSONを通常の画面へ流さない。利用者に必要な変更差分と、実際の短い状態だけ表示する。

## 6. UIは追加より整理を優先する

外観はGoal 003〜005の紙の編集机を維持する。配色・フォント・フレームワークを全面変更しない。文字を小さくして詰めることは解決としない。

### ホーム

「自分の絵ではじめる」「サンプル」「最近の作品」だけを中心にする。AIモデル選択や診断、技術説明、長い利用案内を常設しない。既存作品一覧の保存・複製・再開機能は壊さない。

### 編集

中央は作品プレビュー。脇は今の工程に必要な操作だけ。

- 絵を選ぶ: 画像入力、選択枠、選び直し。背景の補正は必要時に開く。
- 動きをつける: 方向、距離、絵の大きさを保つ、紙の上限。希望入力は一か所。
- 印刷して作る: 現在の型紙枚数と版、出力、組立ガイドへの移動。

現在の工程の主操作を一つ目立たせる。AI候補が届いた場合は通常設定を候補比較へ置き換えるなど、一つの作業領域で完結させる。さらに別の列や下段へ同じ内容を追加しない。

「AI提案」「手動提案」「解釈結果」「採用履歴」をそれぞれ常設パネルにしない。手動調整は普通の操作として残し、AI依頼は同じ場所で必要時に使う。

候補比較では同縮尺・同基準位置を維持し、変更内容を最大数項目で示す。採用・却下は近接させ、採用前に元の設計を変えない。

モデル名、接続先、上限、詳細ログは「設定」または「詳細」へまとめる。現在の状態は「ローカルAI」「手動で編集中」等の短い表示一つで分かるようにする。毎回モデルを選ぶ操作は要求しない。

### 重要情報は隠さない

保存失敗、未解決の条件違反、古い候補、実物未確認は必要な場面で表示する。画面をきれいにするために重大なエラーを消さない。同じ注意を何か所にも繰り返さず、理由と復帰操作を一か所にまとめる。

紙厚・すき間・座標・ハッシュ・実行ログ・実物の詳しい記録は詳細に残す。整理とは機能削除ではない。

### 狭幅・入力・保存

スマートフォン幅では作品と現在の操作を一列にする。大きな常設AIパネル、多重スクロール、本文やフォーカスを覆う固定ボタンを避ける。任意の見た目の改善のために、移行・Undo/Redo・自動保存・IME保護を後退させない。

## 7. 検証

### 通常の回帰

既存check・E2E・保存・examples・WebKit・コンテナを実際のスクリプトに従って実行。通常CIでモデル取得・実推論・外部推論APIを必須にしない。

ローカル推論試験は別の明示コマンドを追加するか既存の適切な試験へ統合する。例として `smoke:local` を作るなら、package.jsonに実装してから案内する。存在しないコマンドを使用者へ渡さない。

### 実ローカルモデル

最低限、異なる3種類の依頼を通常UI・実サーバー・実Ollama経由で試す。

1. 「あと5mm動かしたい。絵の大きさと紙の枚数は変えない」: 成立する入力で相対変更→検査→採用→PDFを確認。
2. 本当に条件が両立しない依頼: 希望値と代案を区別し、保護条件を緩めない。
3. 「回転させず右へ」等の否定を含む依頼: Goal 006の意味を維持する。真の回転要求とは別にする。

モデルを呼ぶ前にサーバーが拒否したものは、ローカルAIの理解成功に数えない。実推論未実施なら未実施と記録する。

同じ入力に対する手動支援との正確さ、候補までの待ち時間、採用後の出力を比較する。ローカルの応答が遅い場合、ロードと生成のどこが遅いか示す。平均だけでなく各試行の結果・失敗も残す。

ローカルモードに有効なGeminiキーが置かれていても、外部APIへ出ないテストを行う。Ollama停止、クラウドタグ、外部URL、未知ツール、過大応答、中断、古い候補をテストする。

### UI

1440×900、390×844を中心に、ホーム・編集・候補・印刷を同じ入力で変更前後比較する。320px相当と200%拡大、キーボード、タップ代替も回帰確認する。

「同時に見える操作が何から何へ減ったか」「次の行動が分かるか」「詳細へ移した機能が見つかるか」を実ブラウザで確認する。ボタン数だけを機械的に減らして必要操作まで隠さない。

画面・PDFは実出力を確認する。スクリーンショットを撮っただけで目視完了や初見利用者テストとしない。実物の印刷・組立は独立した未確認項目であり、今回は勝手に完了へ変更しない。

## 8. 提出用の構成を混同しない

大会の公式ルールにはGemmaがAI技術の選択肢として記載されている。一方、指定Google Cloud実行プロダクトの利用とデプロイURLは別の条件である。

WSLでローカルGemmaが動いただけで応募要件を全部満たしたと書かない。Cloud Runのlocalhostから、利用者のWSL上のOllamaへ自動接続できるとも説明しない。ローカル推論を外部へ公開するトンネルやポート開放は今回行わない。

クラウドでGemmaを実行するなら、モデルAPI料金とは別に計算資源・保存・転送等の費用がある。無料枠、クーポン、最大インスタンス数を完全な費用ゼロ保証と呼ばない。公開方式と費用上限の決定は独立した作業として残す。

## 9. 統合と最終報告

まずUI整理を独立したまとまりで回帰・統合してよい。環境準備待ちでこの改善まで止めない。ローカルアダプターも検証後にmainへ統合し、実main SHAとCIを確認する。

`docs/goals/007r-local-ai-clean-ui.md` に今回の方針を保存し、既存の接続説明に必要な追記だけ行う。成果物は `artifacts/goal007r/` に整理。モデル重み、個人画像、秘密、巨大ログはGitへ追加しない。

報告は次の順にする。

1. 採用モデル・タグ/digest・量子化・ランタイム、実ローカル推論の実施有無。
2. 通常UIから何が設計変更され、何を守れたか。模擬・手動・実ローカル・実Geminiを別々に表示。
3. 不要な常設表示をどこへ移し、主要導線をどう簡潔にしたか。実画面の比較。
4. 反応時間、使用メモリ、モデル取得容量の実測または未測定。外部推論APIの呼出し有無。
5. 同じ設計版のPDF、検査結果、証拠の実際の保存先。
6. main SHA、実CI結果、未コミット差分、残る実物・利用者・公開確認。
7. 利用者のWSLで実行する正確な起動・確認コマンド。外部APIへ切り替わらないこと。

今回の成果は「設定項目を増やした」ではなく、「API料金を発生させずにローカルAIで制作を試せ、画面は前より簡潔になった」です。未実施の性能・使いやすさ・実物動作を保証しないでください。

### 実ローカル環境と失敗も含む試験

既存ユーザー領域のOllama0.33.3を再利用。CPUはAMD Ryzen9 8945HS、WSLメモリ約14GiB、空きディスク約893GiBを事前確認した。Windows側の通常配置にはOllamaのコマンド・プロセスを確認できず、今回使うものはWSL側の専用プロセス。実推論backendはCPUで、`size_vram=0`。GPU加速を確認済みとはしない。

モデルはgemma4:e2b-it-qat / Q4_0、manifest SHA-256は07ea59a474013479c8b6b802bef095c40e964a1d776ba02f264c0e30e1aede0c。公式メタデータは4.6B、必要Ollama0.30.5以上、Gemma4のライセンスはApache2.0。アプリの対応最低版はAPI仕様を確認した0.33.3。既存ランタイムや他プロジェクトのモデル保存先を変更せず、一モデルだけを専用保存先へ取得した。

標準pullは既存鍵設定で失敗した。鍵を上書きせず、公式registryの同一manifest・全blobを取得して各SHA-256を照合。モデル取得本文4,336,359,085bytes、176.076秒（HTTP/TLS overheadは別）。取得は外部通信であり、完全オフラインとは記録しない。OllamaプロセスへNO_CLOUD=1・loopbackを指定し、実/api/statusのcloud.disabled=trueを確認した。

初回ネイティブ予備試験と通常UIのL1は、返答は届いたがtool_callsがなく候補未生成で失敗した。成功に数えていない。次にJSONアクション方式を明示指定。8192contextでのL1は実モデルが25mm候補を作り、検査・配置まで進んだが、3回目の9346tokensを切捨て禁止によって拒否した。L2は不正な条件変更引数の反復、L3は現在と同じ設計を初回から反復エラーにする問題で停止した。すべて元の作品を保持した。失敗を保存し、JSON引数制約・初回変更なしの扱いを修正した。16384での最初の再試験は、Ollamaの文法生成が長い有限文字列反復を展開しきれず、sampler初期化前に拒否された。サーバーの文字数・応答容量・ツール引数検証は維持し、Ollamaへ渡す文法コピーだけから文字列maxLengthを外した後、以下の実試験で応答・ツール実行を確認した。
