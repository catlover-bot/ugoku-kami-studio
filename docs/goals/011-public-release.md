## 3. 余計なモデル呼出しなしで、検査済み代案を渡す

現行の早期終了は `content.text.trim()` と `fulfillsInterpretation(...)` を条件にしているため、説明文のないツール応答や希望と異なる代案は通常ループへ残ります。実コードで確認したうえで修正します。

**自然文の説明生成と、安全な候補提示を分離してください。**

同じ基準版に対して以下を満たす候補が得られた場合は、プログラムで説明を作り、追加のモデル応答なしでも採用待ちへ進められるようにします。
- 当該モデル応答に含まれる全アクションが処理済み。
- 未処理アクション、未解決のツールエラー、曖昧な重要条件がない。
- 基準版、元の希望、本人の訂正が現在の設計と一致。
- 信頼できるサーバー状態から候補を再構成でき、完全なコア検査を通る。
- 固定条件、選択、紙上限を守っている。
- exactとalternativeを区別でき、変更の出所を保持できる。

代案なら、例えば以下を実データから表示します。
「希望の70mmは、現在の条件と検査した配置ではガイド等の条件に違反します。35mmの代案は寸法・配置を確認できました。絵の大きさと型紙枚数は維持します。実物動作は未確認です。」

70/35mmを固定値にしません。最初の希望の検査結果と、最新候補の検査結果は別に保持してください。35mmを最大可能距離・唯一の正解・希望達成と説明しません。

`fulfillsRequested=false` 等の意味を残し、既存の同縮尺比較と「この案にする／使わない」へつなぎます。新しい確認工程は増やしません。採用までは原本を変えず、採用APIでも再検査します。

安全な候補がないまま回数を使い切った場合も、分かっている違反理由と手動復帰を示します。曖昧さ・拒否・中断・古い版・不正な応答を、catch節で無差別に成功へ変換するのは禁止です。応答内の後続アクションを無視して途中の候補を採用待ちへ昇格させないでください。

実試行は改ざんせず保全します。まず保存済みの応答列をローカルfixtureとして使い、上限3回・説明文なし・代案・採用・同版PDFまで検証します。これは実モデルの新試験ではなく、保存応答による回帰です。
境界値、別寸法、後続アクション失敗、古い版、中断、安全な候補なし、紙上限変更禁止も回帰に含めます。モデル回数や出力上限を増やすだけで解決しません。

## 4. 審査用コードとサーバーの予算決定権を分離する

現在の非公開試験は運用者PCのプロキシ・署名permit・ローカル永続台帳に依存します。この依存を審査員へ持ち込まないでください。

審査用コードは「AIを利用してよいか」の確認だけに使います。コードを知る人がcall permitや残予算を書き換えられる構造にしません。公開計画にある秘密の兼用を解消し、署名を残す場合は審査用コードとは別のサーバー専用秘密にします。単にpermit検査を削除して公開する修正は不可です。

AI受付・各モデル送信前の予約と検査は、Cloud Run側で完結させます。ブラウザから来た残額・呼出し数・承認フラグを信用しません。

既存計画の非公開GCSの小さな状態objectを第一候補にします。generation条件付き更新で、同時受付・再起動後も予約・日次回数・全期間回数・一意call IDを整合させます。台帳書込み成功を待ってから送信します。412や不明な書込み結果で、未予約の送信を行いません。

送信済み不明、未送信、見積もり済み、精算済みを分け、再起動や日付変更で期間予算を初期化しません。重複ID・二重精算・プロセス中断・書込み拒否・応答喪失をテストします。セッション消失時は利用者へ復帰を案内し、自動的に新しい有料依頼を作りません。

台帳へ作品画像・原希望文・アクセスコード・秘密鍵を保存しません。サイズと履歴の保持方法を限定し、全文履歴が際限なく増える設計を避けます。従来のブラウザ保存をクラウド作品保存へ勝手に変更しません。

公開用の永続制御と旧試験用の固定3.90ドル／署名permitを混在させません。共通化できる検査・使用量観測は再利用します。新しい会員管理や大きな運用ダッシュボードは不要です。

## 5. 利用上限・費用・停止

既存案に沿い、全利用者合計でAI10依頼/日・30モデル送信/日、全期間600依頼・1,800送信、開始2/分・4/時、同時推論1を上限とします。1依頼は最大6モデル／4ツール／90秒、入力32,768bytes・出力設定2,048tokensを維持します。
リリース前確認もこの公開期間の費用と回数に算入します。失敗・中断の扱いを一貫させ、429対策で上限を迂回しません。

日単位のリセットはJSTの境界を定義し、全期間累積額・送信済み不明分は残します。日次・回数・費用・期限のどれかに達したら追加AIを開始しません。台帳不調時もAIは停止し、手動制作は可能な範囲で維持します。

未認証のAI依頼は、モデルにも予約更新にも進めません。アクセスコード失敗、画像アップロード、異常に大きい入力にも制限を設けます。ブラウザ内ボタンを隠すだけでは対策にしません。認証・秘密・入力本文をログへ出しません。

モデル予算だけでなく、一般の手動アクセスによるCloud Run・ログ・転送・画像検証の費用を計画に含めます。`min0/max1`だけで料金が一定になるとは説明しません。Cloud Runは既存の非同期処理が成立するCPU割当を維持し、課金方式変更だけを先行させません。AI終了後の不要なポーリングや、温存目的の定期アクセスを停止し、監視自体が常時稼働を作らないことも確認します。

日次点検の通知と、閾値／期限の実際の停止手段を区別してください。運用者のWSLやこのチャットが常時動いている前提にはしません。必要な小さな監視・期限停止を既存Google Cloud機能で実装する場合もインフラ枠に算入し、専用対象だけの権限を与えます。

通知だけで厳密な100ドル停止を保証せず、余裕を持った見積もり・停止条件を記録します。AI停止、サービス非公開化／停止、費用が残る保存物を分けます。インフラ枠の超過が見込まれる場合、AIを止めるだけでは足りないことを扱います。

12月1日まで審査可能な状態を目標にしますが、予算到達で止まる条件との両立を無条件に保証しません。枠の残量と停止リスクは事前に通知する構成にし、予算増額は自動承認しません。期限後の停止対象と監査記録の保全も設定してください。

## 6. 同じ公開候補を検証して、そのまま公開へ進む

実装・ローカル回帰・CIの後、公開用の1サービスをまずIAM非公開で配置します。実Vertex＋実GCSの予約・精算・拒否・再起動後の状態を確認します。

リリース前の実AI確認は、診断・失敗・再試行を含め最大6依頼・合計24送信に絞り、全体予算にも算入します。既存と同じ成功録画を増やすための生成は不要です。

優先する確認：
1. C相当の条件で、実検査した違反理由と採用可能な代案を通常UIへ渡せる、または代案がない理由を正しく示せる。
2. 採用した設計版からPDF・組立ガイドが一致する。
3. 中断とその後の別依頼、原本と保存の保持。
4. 2クライアントや再起動を挟んでも、予算と重複制御が失われない。基盤の競合試験はモデル不要の経路も利用する。
5. 正しいコードがない経路・不正permit・不足予算・停止状態から実モデル送信が発生しない。

保存応答fixtureの35mmが新しい実AIから必ず返るとは仮定しません。実際の代案値と検査の根拠で判断してください。

合格後、Web/UIと手動APIに必要な範囲を公開し、AIアクセスコード認証は維持します。Cloud Runの公開設定によりAIまで無認証にしません。GCS・Secret・内部APIを公開しません。

Google未ログインの新規ブラウザで、実HTTPS URL→手動制作→審査用コード→実AI→比較・採用→PDFを確認します。運用者のlocalhostプロキシや独自ヘッダーを使わない経路にしてください。コードはGit・動画・公開資料から除外します。

ここで合格したサービスは提出用URLとして維持します。以前の「試験終了後はすべて削除」の指示を、この公開版へ適用しません。非公開検証で重大問題が出た場合はAIを無効のままにし、実装可能な修正を行い、予算内で再検証します。枠外や外部制約に当たった場合だけ、必要な変更をまとめて報告します。

既存の作品中心・3工程・希望入力一か所・候補比較が通常操作を置き換える構成を維持します。台帳、トークン、署名、詳細なモデル設定を制作画面へ増やしません。

429は実際のRetry-After等があれば待機を表示し、不明なら秒数を捏造しません。自動再送しません。制限・中断・失敗後も原本を編集・保存できることを確認します。

印刷・組立・実物写真は本人の作業として残します。既存の第3版PDFと版固定ガイドを一つ指定して渡し、100%印刷・50mm線・接着・保持・往復動作を記録してもらいます。実物未検証でもソフトウェアの技術デモ公開は進められますが、「必ず工作が動く」「完成品を実証済み」とは表示しません。初見利用者の実証も自動テストとは分けます。

YouTube投稿とZenn最終提出は本人が行います。新機構、SNS、画像生成、別課金モデル、動画の全面作り直しは追加しません。
